# Guided practice: beginner to intermediate

Only use these exercises against your own Juice Shop instance. Start with manual observation and built-in challenges. Avoid testing real websites or accounts.

## Exercise 1 — Map the normal application

**Goal:** Learn how a browser talks to a server.

1. Open Juice Shop in Burp's built-in browser.
2. Visit the home page, search, product details, and login page without entering real credentials.
3. In **Proxy → HTTP history**, identify a page request, a static asset request, and an API/XHR/fetch request if present.
4. Record each request's method, path, status code, and content type.
5. Explain the difference between a request and a response.

**Evidence to save:** A short table with method, path, status, and what you think the request does. Redact cookies, tokens, and personal data.

## Exercise 2 — Parameters and validation

**Goal:** Understand client-side versus server-side validation.

1. Use a harmless search term in the app.
2. Find the corresponding request in HTTP history.
3. Send the request to Repeater.
4. Change only the search value to another ordinary string and resend it.
5. Compare the response. Note which validation is visible in the UI and which behavior is enforced by the server.

Do not send high-volume payloads or test another host.

## Exercise 3 — Authentication concepts

**Goal:** Learn how sessions work without targeting real accounts.

1. Open the app's login page and inspect the requests generated by the UI.
2. Identify where the browser sends a login request and how the server responds.
3. Look at response headers and cookie attributes when present.
4. Use only test accounts created inside your own lab. Never reuse a real password.
5. Explain why authentication, authorization, and session management are separate controls.

Do not publish session cookies or tokens in screenshots.

## Exercise 4 — SQL injection concepts

**Goal:** Learn to recognize unsafe query handling in a deliberately vulnerable app.

1. Open Juice Shop's built-in scoreboard/challenge guidance.
2. Choose a beginner SQL injection challenge and read its hints.
3. Work through the challenge using the app and Burp only against your lab host.
4. Observe how input changes server behavior, and write down the root cause and a defensive fix (parameterized queries and safe error handling).
5. Reset/restart the lab if you want a clean state.

Use the built-in challenge workflow rather than applying payloads to any external login form.

## Exercise 5 — Cross-site scripting (XSS) concepts

**Goal:** Understand the risk of untrusted input being interpreted as executable browser content.

1. Select a beginner XSS challenge from the local scoreboard.
2. Read the challenge hint and identify the input and output context.
3. Complete the challenge only in your local instance.
4. Document the context-sensitive output encoding or safe DOM API that would prevent the issue.
5. Do not use real session data or create payloads intended to persist for other people.

## Exercise 6 — Access control / IDOR

**Goal:** Understand why changing an object identifier must not grant access to another user's data.

1. Use only lab accounts and data you created.
2. Inspect requests for an object you are allowed to view.
3. Follow a local scoreboard challenge and its hints to test authorization boundaries.
4. Record the expected versus actual result.
5. Recommend server-side ownership checks and deny-by-default authorization.

Never test another person's real account or data.

## Exercise 7 — Write a concise finding

Use this template:

- **Title:** Clear vulnerability and affected feature
- **Environment:** Local Juice Shop version, browser, and tool versions
- **Preconditions:** Test account/data created in the lab
- **Steps to reproduce:** Minimal steps, only against the lab
- **Expected result:** Secure behavior
- **Actual result:** Observed behavior
- **Impact:** What an attacker could realistically do
- **Evidence:** Redacted request/response or screenshot
- **Remediation:** Specific defensive change
- **Retest:** How you confirmed the fix

## Suggested learning order

1. HTTP requests and responses
2. Authentication and session cookies
3. Input validation
4. SQL injection
5. XSS
6. Access control
7. Security headers and error handling
8. Report writing and remediation

For complete official challenge explanations, consult the [OWASP Juice Shop Companion Guide](https://pwning.owasp-juice.shop/).
